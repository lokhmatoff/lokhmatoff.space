## Почему оно работает так

1. Пробы **PARA** и **Zettelkasten** не окупились — нет регулярности, удобной структуры и энтузиазма фиксировать знания и мышления / вести заметки;
2. Способ организации хранилища и работы с ним, предложенный [[Steph Ango|kepano]], очень откликнулся. Хочу писать свободно и без заморочек;
3. Моя цель состоит не в создании базы знаний, пригодной для научных работ. Две главных задачи хранилища — публичные знания и жизненный опыт, накопленные за годы в цифре + LifeOS для персональных нужд;
4. Предыдущие системы переусложнены. Эта призвана сохранять мой поток мышления таким, какой он есть;
5. Эпоха меняется — хоть письменные заметки и полезны, человек их будет редко читать. ИИ агенты **уже** являются частью общего поля в интернете, поэтому мои знания предназначены и для людей, и для агентов.

История хранилища начинается с 2024 года. Накопленное лежит в `_DEFINITELY_LEGACY/` и поднимается по мере необходимости, а не массовой миграцией.

## Принципы

1. **File over app** — стандартный Markdown, переносимость, долговечность формата;
2. **Без делегации осмысления** — финальное слово за мной как за автором. Агент помогает мне думать и структурировать, не заменяет понимание;
3. **Писать важнее, чем настраивать** — рефакторинг и райсинг окружения не должны вытеснять реальную работу с хранилищем и написание заметок;
4. **Эволюция заметки** — сырая journal-заметка → вечнозелёная заметка в том же файле, без дублирований. Обогащение и переосмысление важнее, чем количество;
5. **Категории, не теги** — типизация заметок через [[Категории]], а не *теги*, последние требуются только для пометок ***вне предметной области*** заметок;
6. **Рабочие заметки отдельно** — всё, что касается проектов по работе (под NDA), должно находиться в отдельном соответствующем хранилище, никаких объединений;
7. **Гибкий уровень атомарности** — мелкая гранулярность мыслей для быстрых (журнальных) заметок, допустимая варьируемая гранулярность для вечнозелёных заметок. Последние могут быть как мыслями, так и постами / статьями;
8. **ID для всего** — фиксация зарождения мысли или появления в моей жизни объекта внешнего мира, история эволюции мышления и кругозора.

## Решаемые проблемы

| Проблема | Как решаем |
| -------- | ---------- |
| Смешались несколько систем, схема свойств плывёт | Одна схема, шаблон на каждый тип заметки |
| Не помню, есть ли у меня что-то про X | `id`, категории, Bases, свободные викиссылки |
| Пишу нерегулярно | Журнальные заметки + еженедельный обзор |
| Нет места для чужих текстов и внешних объектов | `clippings/`, `references/` |
| Рабочее и личное в одном хранилище | Отдельные волты для NDA-проектов |

## Типы заметок

### Journal (журнальная заметка, сырая фиксация)

Моментальный захват мыслей, наблюдений, идей, вопросов и подобного. Живёт в корне хранилища.

- **Имя файла:** `YYMMDDHHmm Название.md` (например, `2608010308 Различаемость названий журнальной и вечнозелёной заметок.md`)
- **Frontmatter:** `id` (сохранение с момента журналирования), опциональный `title`, `aliases` (включая `id`), `date`, опциональные `categories` (список вики-ссылок на заметки-категории), булевый `private` (по умолчанию `false`, для быстрого переключения при необходимости), `tags: [journal]` (тегом помечается мета-признак, что заметка *журнальная*)
- **Содержание:** сырой текст без полировки; викиссылки приветствуются, но не обязательны
- **Участие агента:** приоритетное, учитывается агентом в анализе и обсуждается мной и агентом-соавтором

### Evergreen (вечнозелёная заметка)

Зрелая заметка, написанная **своими словами**. Может быть постом, статьёй, аналогом цеттеля. Обычно является результатом эволюции журнальной заметки. Живёт в корне хранилища.

- **Имя файла:** утверждение-заголовок без ID (например, `Регулярность как признак эволюции мышления.md`)
- **Frontmatter:** как у journal-заметки, но без метатега
- **Содержание:** атомарная мысль/цеттель/статья/длиннопост/эссе — что угодно за моим авторством, композируемая, готовая к публикации в зависимости от `private`
- **Участие агента:** почти нет, только по моей просьбе

### Reference (референс, ссылочная заметка)

Объект внешнего мира: книга, человек, приложение, конференция, рецепт и так далее. Живёт в директории `references/`.

- **Имя файла:** по названию объекта (например, `Гарри Поттер.md`, `Obsidian.md`, `Steph Ango.md`, `ТОЛК 2026.md`, `Нячанг.md`)
- **Frontmatter:** `id`, `title` (переопределяемый бэкап названия заметки, может быть полезен для Quartz-сайта), `aliases` (включая `id`), `date`, `categories: [ "[[Книги]]", "[[Люди]]" ]` (или любые другие [[Категории]]), `private` (default — `false`, может быть выключенным в зависимости от потребностей), свойства шаблона конкретной категории
- **Шаблон:** по категории (Книги, Люди, Приложения — расширение по мере необходимости)
- **Содержание:** метаданные + заметки о взаимодействии с объектом
- **Участие агента:** минимальное, по запросу от меня

### Category (категория)

Индексная заметка для группы ссылочных заметок или темы. Вдохновлено методом [[Steph Ango|kepano]]. Живёт в корне хранилища.

- **Примеры:** `Книги.md`, `Люди.md`, `Приложения.md`
- **Содержание:** опциональное краткое описание, встроенные представления **Obsidian Bases** для заметок этой категории
- **Участие агента:** минимальное, по запросу от меня
- **Не путать с директориями** — заметка-категория ≠ директория

### Weekly (еженедельная заметка)

Главный якорь [[LifeOS]]. Включает в себя *задачи*, *фокусы*, *обзор* журнальных заметок на неделю. Живёт в `weekly/`. ***Не экспортируется*** в публичный Quartz.

- **Имя файла:** `YYYY-Www.md` (например, `2026-W31.md`)
- **Frontmatter:** `id`, `startDate` (начало недели), `endDate` (конец недели), `tags: [weekly]`
- **Участие агента:** только мониторинг, правки ручные

### Clipping (клиппинг)

Чужой текст из интернета. Формируется автоматически при применении браузерного расширения [[Obsidian Web Clipper]]. Является своеобразным публичным артефактом списка «для чтения». Живёт в `clippings/`.

- **Frontmatter:** `id`, `title`, `date`, `aliases` с `id`, `source` (URL клиппируемой страницы), `categories` при необходимости, `tags: [clippings]`
- **Переработка в вечнозелёную заметку:** в редких случаях, в основном клиппинг остаётся клиппингом по онтологии оцифрованного текстового артефакта из внешнего мира, допустимо использование в линковке в референсах или журнальных/вечнозелёных заметках
- **Участие агента:** нулевое, допустимо использование ссылки на клиппинг при генерации текста заметок

## Эволюция журнальной заметки в вечнозелёную

Рассматриваю три сценария:

1. **Еженедельный обзор** — я самостоятельно просматриваю журнальные заметки за неделю и переписываю их своими словами;
2. **Мозговой штурм с агентом** — агент помогает мне сформировать мыслительный процесс для переписывания, я пишу итоговый вариант;
3. **Агентированная эволюция** — агент предлагает кандидатов на «озеленение» и черновик, я утверждаю или правлю.

В любом из сценариев ниже эволюция включает:

- переписывание своими словами (не просто переименование заметки);
- переименование файла заметки — убрать `id` из имени файла, оставить только название-стейтмент;
- сохранение `id` в frontmatter и `aliases` для стабильности ссылок и мониторинга истории формирования новых знаний/артефактов;
- удаление тега `journal`;
- финальное слово и правки — за мной, не агентом.

Эволюция *возможна вне weekly*, когда конкретная заметка или мысль будет считаться «созревшей».

## Структура папок

```
/
├── index.md              # Домашняя страница и встраиваемые Bases
├── *.md                  # Журнальные и вечнозелёные заметки
├── attachments/          # Медиавложения
├── clippings/            # Клиппинги из Obsidian Web Clipper
├── references/           # Референсы (Книги, Люди, Приложения...)
├── templates/            # Шаблоны (+ bases/ внутри)
├── weekly/               # Еженедельные заметки
└── _DEFINITELY_LEGACY/   # Замороженный непубликуемый legacy, по запросу
```

Папки нужны для *физического хранения*.

## Свойства (frontmatter properties)

### Обязательные для всех типов

| Свойство  | Тип     | Описание                                                                                 |
| --------- | ------- | ---------------------------------------------------------------------------------------- |
| `id`      | Текст   | `YYMMDDHHmm` — якорь для Quartz, сортировки и алиасов                                    |
| `title`   | Текст   | Название заметки (без ID), везде, кроме Weekly-заметок                                   |
| `date`    | Дата    | Дата создания                                                                            |
| `private` | Чекбокс | Выключен по умолчанию. При `true` не попадает в Quartz                                   |
| `aliases` | Список  | Алиасы для линковки. Для всех типов заметок обязательно включает ID заметки `YYMMDDHHmm` |

### Дополнительные свойства

| Свойство     | Тип                                | Область применения                                                                                |
| ------------ | ---------------------------------- | ------------------------------------------------------------------------------------------------- |
| `categories` | Список                             | Ссылочные, вечнозелёные заметки, иногда клиппинги и журнальные заметки — `[[Книги]]`, `[[Люди]]`… |
| `tags`       | Список тегов (нативное в Obsidian) | Мета-пометки: `journal`, `weekly` `featured`…                                                     |
| `source`     | Текст                              | Для клиппингов — URL источника                                                                    |

Возможны и другие свойства, но они специфичны для каждого шаблона. Имена свойств — на английском, **camelCase**. Содержание заметок — на любом языке (основной — русский).

## Категории

Начинаю с минимально необходимого набора и расширяю по мере необходимости. Сейчас доступны:

- [[Книги]]
- [[Люди]]
- [[Приложения]]

### Правила для категорий

1. Категории — множественное число (как у **kepano**);
2. Заметка-категория = индекс + представление **Obsidian Bases**, не директория/папка;
3. Для вечнозелёных/журнальных заметок и клиппингов `categories` опциональны; для ссылочных заметок — *обязательны*.

---

## Теги

Только внедоменные пометки для мета-разделения, не дублируют [[#Категории]].

| Тег        | Назначение                      |
| ---------- | ------------------------------- |
| `journal`  | Сырая заметка, ещё не evergreen |
| `review`   | Требует еженедельного обзора    |
| `featured` | Интересно сейчас                |
| `weekly`   | Еженедельная заметка            |

Новые теги я должен добавлять ***только при явной необходимости***.

---

## Связи между заметками

1. **Викиссылки** в тексте — основной способ связи;
2. **Категории** — навигация второго порядка;
3. **Obsidian Bases** — динамические представления по свойствам / категориям.

Без `next` / `parent` связок и без формализованных систем цепочек. Связывание — естественный процесс, а не ритуал.

## Ритуалы

### Ежедневная цель

Создание журнальных заметок при появлении мыслей. Не *ежедневные заметки* — отдельные файлы в корне хранилища с таймштампом в качестве `id`.

### Еженедельный обязательный минимум

1. Обзор журнальных заметок за неделю;
2. Эволюция созревших журнальных заметок в вечнозелёные;
3. Фиксация задач и фокусов в еженедельных заметках;
4. Опционально: обзор / проверка с агентом-ассистентом.

### Ежемесячные / Ежегодные ритуалы

Не внедряются сейчас. Возможны позже, когда ведение еженедельных заметок станет *устойчивой* привычкой.

## Публикация заметок в Quartz

Правила:

1. Пайплайн — это хранилище → репозиторий с Quartz → https://lokhmatoff.space;
2. Публикуется всё с `private: false` (вечнозелёные, журнальные, ссылочные заметки, заметки-категории, клиппинги);
3. Не публикуются заметки с `private: true`, еженедельные заметки;
4. Шаблоны по умолчанию — `private: false`, для чувствительного контента `private: true`.

### Рабочие хранилища Obsidian

Рабочие заметки размещаются в отдельных волтах. Этот волт не должен содержать [[NDA]]-контент.

Инсайты из работы, пригодные для публикации, переписываются в вечнозелёные заметки **без** NDA-деталей.

## Роль ИИ-агентов

> [!tip] Конкретно я использую [[Cursor Agents]]

### Правила для агентов

1. Агенты — равноправные «граждане» в хранилище (first-class citizens);
2. При этом агенты являются **соавторами**, а не авторами;
3. Агенты помогают со структурой, линковкой, эволюцией **journal** → **evergreen**;
4. Агенты предлагают кандидатов на эволюцию заметок;
5. Агенты могут участвовать в еженедельном ревью как собеседники;
6. Агенты **не** создают вечнозелёные заметки без моего утверждения;
7. Агенты **не** запускают настройки/рефакторинг без запроса.

---

## Guardrails (антипаттерны)

1. **Не рефакторить без написания** — если за неделю 0 журнальных заметок, рефакторинг нежелателен;
2. **Не добавлять типы заметок** без явной необходимости (сейчас 6 — этого достаточно);
3. **Не плодить теги** — если можно выразить через категории или викиссылки;
4. **Не переименовывать без переписывания** — переименование ≠ зрелость;
5. **Не тащить рабочее в личный волт** — отдельные хранилища;
6. **Не мигрировать легаси массово** — только по запросу.

### Принял

| Практика | Как у меня |

| У kepano | У меня |
| -------- | ------ |
| Ежедневные заметки в папке Daily | Еженедельные в `weekly/` |
