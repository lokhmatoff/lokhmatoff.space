# Спецификация редизайна Lokhmatoff Space

## 1) Контекст и цель

Проект работает на `Quartz 4` (`Preact + SCSS`) и уже имеет кастомный layout.
Цель редизайна: получить современный, аккуратный и стабильный визуал в духе FluxUI / shadcn / Cursor Docs **без миграции на Tailwind/UI-кит** и без полного переписывания компонентов.

## 2) Обязательные вводные (зафиксировано)

1. **Нивелировать тему Everforest**: перестать опираться на её выраженный “green/orange” характер как на визуальный стиль сайта.
2. **Документный минимализм**: спокойная типографика, чистая иерархия, достаточно воздуха, минимум декоративного шума.
3. **Унификация поверхностей**: единый язык для header/search/cards/list/sections (радиусы, границы, тени, состояния).
4. **Hero на главной**: добавить hero-блок для `index`, но сохранить и корректно показать существующий markdown-контент `content/index.md`.

## 3) Non-goals (что не делаем в этом цикле)

- Не меняем движок (остаёмся на Quartz).
- Не внедряем shadcn/FluxUI как библиотеку (берём визуальные принципы, не код).
- Не переделываем структуру контента заметок массово.
- Не делаем большой продуктовый редизайн навигационной логики (только визуал и UX-полировка текущей структуры).

## 4) Дизайн-принципы

1. **Clarity first**: читаемость выше декоративности.
2. **One surface language**: одинаковое поведение и форма всех контейнеров.
3. **Soft contrast**: нейтральные фоны и границы, акцент только для интерактивных элементов.
4. **Predictable interactions**: единые `hover / focus-visible / active`.
5. **Content-first homepage**: hero усиливает вход, но не затмевает собственное содержимое `index.md`.

## 5) Визуальная система (Design Tokens v1)

Ниже целевые семантические токены (названия; точные значения подбираются в фазе Foundation):

- `--bg`: базовый фон страницы
- `--bg-elevated`: фон приподнятой поверхности (карточки/модалки)
- `--text`: основной текст
- `--text-muted`: вторичный текст
- `--border`: базовая граница
- `--border-strong`: акцентная граница
- `--accent`: брендовый/интерактивный акцент
- `--accent-contrast`: текст на акценте
- `--ring`: цвет focus-ring
- `--shadow-sm`, `--shadow-md`: стандартные тени
- `--radius-sm`, `--radius-md`, `--radius-lg`: радиусы
- `--space-*`: шкала отступов

### Базовые визуальные правила

- Радиусы: умеренные, консистентные (`8/12/16` по ролям).
- Границы: преимущественно `1px`, нейтральные.
- Тени: мягкие, только на elevation-сценариях.
- Плотность: больше вертикального ритма (особенно между секциями и карточками).
- Анимации: быстрые и спокойные (`120-180ms`, без агрессивного spring).

## 6) Архитектурный подход для Quartz

### 6.1 Где лежит редизайн

- `quartz/themes/*.ts` — палитры light/dark.
- `quartz/styles/custom.scss` — центральная “точка сборки” кастомной визуальной системы.
- `quartz/styles/base.scss` + `quartz/styles/variables.scss` — сетка/ритм/глобальные правила.
- `quartz/components/*` и `quartz/components/styles/*` — локальные компонентные стили.

### 6.2 Стратегия “token-first”

1. Сначала токены и глобальные правила.
2. Потом каркас и surfaces.
3. Затем точечная адаптация компонентов.
4. В конце — homepage hero и polish.

Это исключает “лоскутный” редизайн, когда каждый компонент стилизуется по-разному.

## 7) Спецификация главной страницы (Hero + index content)

## Требования к hero

- Отображается **только** на главной (`slug: index`).
- Содержит:
  - короткий заголовок/позиционирование,
  - 1-2 строки описания,
  - primary CTA (например, “Читать заметки”),
  - optional secondary CTA (например, “Обо мне” / “Проекты”).
- Вписывается в общий surface language (те же радиусы/границы/тени).

## Требования к существующему контенту `content/index.md`

- Контент из `index.md` **не удаляется** и рендерится как и раньше.
- Hero идёт **перед** markdown-контентом, а не вместо него.
- Нужен комфортный отступ между hero и `article`.
- В мобильной версии hero не должен занимать избыточную высоту.

## Рекомендуемая техническая реализация

- Добавить отдельный компонент (например, `HomeHero`) и подключить его в layout для главной страницы.
- Логику “показывать только на index” держать в компоненте или в месте композиции layout.
- Не хардкодить основной текст hero в нескольких местах: один источник конфигурации.

## 8) Унификация поверхностей (Surface System)

Единая спецификация для:

- header контейнера,
- поисковой кнопки и search overlay,
- списков (`PageList`, теги, recent),
- блоков в footer и secondary секциях.

### Правила

- Общая форма: единые радиусы и border.
- Состояния интерактива: hover/focus одинакового “семейства”.
- Типографика внутри surfaces: единые размеры и насыщенность (мета, заголовки, ссылки).
- “Приподнятость” использовать дозированно: overlay > card > flat.

## 9) Поэтапный план выполнения (для Cursor)

Каждая фаза должна быть отдельной задачей/мини-планом.

### Фаза 0 — Baseline & Audit

**Результат:**
- Зафиксирован список затрагиваемых файлов.
- Подготовлен “до” скриншотный baseline (desktop + mobile).

**Критерии приёмки:**
- Понятен scope изменений.
- Есть согласованный список компонентов первой волны.

### Фаза 1 — Foundation (Tokens + Theme reset)

**Результат:**
- Everforest-визуал нивелирован нейтральной палитрой.
- Введены семантические токены для light/dark.
- В `custom.scss` описаны базовые глобальные правила нового стиля.

**Критерии приёмки:**
- Нет “кислотных” акцентов Everforest в основных поверхностях.
- Контраст текста и ссылок адекватен.
- Тёмная/светлая темы визуально согласованы.

### Фаза 2 — Layout & Rhythm

**Результат:**
- Обновлён общий ритм отступов.
- Приведены к единому виду контейнеры header/content/footer.
- Адаптивы не ломаются на mobile/tablet/desktop.

**Критерии приёмки:**
- Визуальная иерархия читается с первого взгляда.
- Нет визуальных “провалов” между секциями.

### Фаза 3 — Surface Unification (Core Components)

**Результат:**
- Header/Search/Footer/PageList/TagList/RecentNotes выглядят как одна система.
- Унифицированы hover/focus/active состояния.

**Критерии приёмки:**
- Поверхности не конфликтуют между собой.
- Все ключевые элементы интерфейса соответствуют единым токенам.

### Фаза 4 — Homepage Hero

**Результат:**
- На главной появился hero.
- Контент `content/index.md` сохранён и корректно отображается ниже hero.

**Критерии приёмки:**
- Hero работает только на главной.
- Markdown-контент главной не потерян и не дублируется.
- На мобильном нет перегруженности первого экрана.

### Фаза 5 — Polish & Accessibility

**Результат:**
- Вычищены визуальные несостыковки.
- Добавлены/проверены focus-visible и интерактивные состояния.

**Критерии приёмки:**
- Нет очевидных регрессий по читаемости.
- Управление с клавиатуры не ухудшилось.

## 11) Риски и контроль

- **Риск:** локальные стили компонентов будут “перетягивать” токены.  
  **Контроль:** сначала обновить базу и только потом компонентные override.

- **Риск:** hero поломает ожидаемый контентный поток главной.  
  **Контроль:** обязательный smoke-check: hero + markdown `index.md` вместе.

- **Риск:** редизайн станет “полузавершённым”.  
  **Контроль:** работа строго по фазам с отдельными критериями приёмки.

## 12) Итоговое определение “готово”

Редизайн считается успешным, если:

1. Визуально ушли от Everforest-идентичности к нейтральному документному стилю.
2. Все основные поверхности подчиняются единой системе.
3. Главная имеет hero и при этом сохраняет собственный markdown-контент.
4. Изменения внедрены поэтапно, с контролируемыми рисками и без архитектурного “разлома”.
